# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

Inputs below were checked against a verbatim copy of the starter helpers (Python 3.13); endpoint symptoms follow directly from the starter code. Rule numbers (R1-R10) refer to `openapi.yaml`.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes`, the `> 10` test | Compares the *floored* minutes with 10, so a punch-in 1-59 s past the 10:00 grace is treated as on time. R2 says "strictly more than 10:00". | Shift 09:30, punch-in 09:40:01 returns 0, expected 10. 09:40:59 also returns 0. | Compare elapsed *seconds* with 600; when late, return `seconds // 60`. |
| 2 | `compute_late_minutes`, `punch_in.replace(...)` | Builds the shift start on the punch-in's own calendar date, in whatever time zone the datetime happens to be in (UTC/server-local, never IST). Shift times are IST (R1). It also breaks overnight shifts: a 00:30 punch-in for a 22:00 shift is measured against 22:00 *that* day. | Server in UTC, punch-in 10:05 IST: the datetime is 04:35 UTC, compared with 09:30 UTC, giving -295 min, so 0 instead of 35. Overnight 22:00 shift, punch-in 00:30 IST: expected 150, got a negative number, so 0. | The shift start is built in IST on the *attendance date* (R1) via `attendance_date()` + `_at_ist()`. |
| 3 | `compute_late_minutes`, `int(x / 60)` and no truncation to whole seconds | `int()` truncates toward zero (not floor) and sub-second parts are not removed (R1 says instants are truncated to the second first). | 09:40:00.900 should count as 09:40:00 (0 late). | Instants are truncated on entry (`from_ms`, `truncate`); integer `//` on whole seconds. |
| 4 | `compute_work_hours`, `round(..., 2)` | Python's `round` on a float is not half-up (R4): it is banker's rounding on a binary approximation. | 7 h 07 min 30 s = 7.125 h: starter gives 7.12, R4 requires 7.13. Roughly half of all exact-tie durations differ (1390 of the 2778 tie cases below 100 000 s). | Exact `Decimal(seconds) / 3600` quantized with `ROUND_HALF_UP`; inputs truncated to seconds. |
| 5 | `compute_overtime`, no 30-minute threshold | Returns every positive minute. R3 counts overtime only when it reaches 30. | Punch-out 18:31 for shift_end 18:30 returns 1 (expected 0). | Return the floored minutes only if `>= 30`, otherwise 0. |
| 6 | `compute_overtime`, `fromisoformat(date_str).replace(tzinfo=IST)` | Always puts shift_end on the attendance date, so it is wrong for overnight shifts (shift end is the *next* day). It is also called with a punch-out that is naive (`TypeError: can't subtract offset-naive and offset-aware datetimes`) with the starter's own naive datetimes. | 22:00-06:00 shift, date 2026-07-06, punch-out 06:40 next day: starter returns 1480, expected 40. | `compute_overtime` adds a day when the shift is overnight (`shift_end <= shift_start`); all datetimes are timezone-aware. |
| 7 | `create_employee`, `find_one` then `insert_one` | Check-then-insert race and no unique index, so parallel creates can both succeed and produce duplicate `emp_code`s. | 8 parallel `POST /employees` with the same code: several 201s. | Unique index on `emp_code` created at startup; `insert_one` and catch `DuplicateKeyError` -> 409. |
| 8 | `EmployeeIn` / `create_employee` | No validation: any `emp_code`, email, shift format, `joined_on`; `shift_start == shift_end` accepted. `created_at` is `datetime.now()` (naive local time), and returned as an ISO string instead of epoch ms. | `emp_code: "x"`, `joined_on: "2026-13-45"`, `shift_start: "25:99"` all return 201. | Pydantic patterns/lengths from `openapi.yaml`, real-date check, `shift_start != shift_end`, `created_at` stored as UTC and returned as epoch ms. |
| 9 | `list_employees`, `skip = page * page_size` | Off by one page: page 1 skips the first `page_size` rows (R10: page starts at 1). | `GET /employees?page=1` never shows the first employees. | `(page - 1) * page_size`. |
| 10 | `list_employees`, `count_documents({})` and no sort/bounds | `total` ignores the department filter (R10), results are not sorted by `emp_code`, and `page_size` / `page` have no bounds (`page_size=0`, negative or huge values, `page=0` give wrong results or a 500 from a negative skip/limit). | `?department=Sales` returns `total` for the whole collection. | `count_documents(q)`, `sort("emp_code")`, `Query(ge=1, le=100)` for `page`/`page_size`. |
| 11 | `punch_in`, `emp = find_one(...)` unused when `None` | No 404 for an unknown employee: `emp["shift_start"]` raises `TypeError` -> 500. | `POST /attendance/punch-in {"emp_code": "NOPE"}` -> 500. | `get_employee()` raises 404. |
| 12 | `punch_in`, `datetime.fromtimestamp(ms / 1000)` and `ts.date()` | Uses the *server's* local time zone and a naive datetime, not IST (R1); no truncation to seconds; `if body.punched_at` treats 0 as "missing"; any int is accepted (seconds, negative, huge) where the contract requires 422. | Punch-in at 20:00 UTC (01:30 IST next day): `date` is the UTC/server date, not the IST date. `punched_at` in seconds is accepted and stored in 1970. | `punched_at` is a strict int in `[1e11, 4102444800000]` (422 otherwise, floats/strings/bools rejected); converted with `datetime.fromtimestamp(ms // 1000, tz=UTC)`; the date comes from `attendance_date()` (IST + overnight rule). |
| 13 | `punch_in`, `find_one` then `insert_one` | Same check-then-insert race: two simultaneous punch-ins both pass the check, two documents for the same (emp, date). There is no unique index. | 16 parallel identical punch-ins: several 201s and duplicate rows. | Unique index `(emp_code, date)`; `insert_one` + `DuplicateKeyError` -> 409 (exactly one 201). |
| 14 | `PunchInIn.status: str` | Any string accepted, including `ABSENT`, `LEAVE` and garbage, which punch-in must reject. | `status: "ABSENT"` with a punch time -> 201 with a contradicting record. | `Literal["PRESENT", "WFH", "ON_DUTY"]` -> 422. |
| 15 | `punch_in` response | Leaks `id` (ObjectId string), returns `punch_in` as a datetime object (serialised as an ISO string) instead of epoch ms; the starter `late_minutes` came from the buggy helper. | Response has `"id"` and `"punch_in": "2026-07-06T10:05:00"`. | `record_out()` builds the API shape: no `_id`/`id`, epoch ms for every instant. |
| 16 | `list_attendance`, `list(db.attendance_logs.find(q))` + Python sort/slice | Loads the whole result set into memory and sorts in Python; no index, so a `COLLSCAN`; `total = len(docs)`. Dies on 100k records. Sort has no `emp_code` tie-break (contract: date desc, emp_code asc). | `GET /attendance` on 100k docs: slow and memory-hungry; ties come back in arbitrary order. | Database-side `sort` / `skip` / `limit` + `count_documents`, backed by the `(date desc, emp_code)`, `(emp_code, date)` and `(status, date desc, emp_code)` indexes. |
| 17 | `list_attendance`, filters and paging | `page=0` -> negative slice (silently wrong rows), `page_size` unbounded, unvalidated `date_from` / `date_to` / `status` (garbage compared as strings), no 422 for `date_from > date_to`. | `?page=0`, `?date_from=banana`, `?status=NOPE` all return 200. | `Query` bounds, strict date parsing, `Literal` status, explicit `date_from > date_to` -> 422. |
| 18 | `list_attendance` output | Returns the raw document: `id` ObjectId string, BSON datetimes (not epoch ms), and seeded legacy records without `history` / `half_day` / `late_minutes` come back without those keys. | A legacy record (DATA_MODEL sample 9) is returned without `history` and `half_day`. | `record_out()` applies defaults (`[]`, false, 0) and epoch ms. |
| 19 | `health` | Always returns `ok`, even when MongoDB is down; the contract requires 503 unless Mongo answers a ping. | Stop MongoDB: `/health` is still 200. | `db.command("ping")`; `PyMongoError` -> 503. |
| 20 | Module level `MongoClient(...)` | Returns naive datetimes (no `tz_aware`), so values are silently interpreted in the server's local zone and any mix with IST-aware values raises `TypeError`; no indexes are created at all (the seeded DB only has `_id`). | `TypeError: can't subtract offset-naive and offset-aware datetimes` as soon as a stored datetime is compared with an IST-aware one (e.g. in `compute_overtime`); otherwise silently wrong on a non-UTC server. | `MongoClient(..., tz_aware=True)`; `ensure_indexes()` at startup (idempotent; retried from `/health` if Mongo was down at boot). |

**Examined and judged fine:** `load_dotenv()` (it does not override variables that are already set, so real environment variables win as the contract requires); reading `MONGO_URI` / `MONGO_DB` from the environment with local defaults; the `IST` constant (+05:30 fixed offset is correct, India has no DST); `doc.pop("_id")` after `insert_one` in `create_employee` (it does remove the id that PyMongo added); the 201 status codes on the two POST endpoints; the idea of storing derived fields at write time (matches DATA_MODEL.md).
